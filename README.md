# Internet Literacy Lab

「失敗できる、架空のインターネット。」メール・SNS・写真・コメント・情報共有・通販・感染警告の模擬画面を操作し、行動の結果と判断理由を確かめる静的Webアプリです。

## 実行する

Node.js 22.12 以降と Bun を使用します。依存関係は `bun.lock` で固定しています。

```sh
bun install --frozen-lockfile
bun run dev
```

表示されたローカルURLをブラウザで開いてください。登録や環境変数の設定は不要です。

```sh
bun run build                    # 型検査と本番用ビルド
bun run preview -- --port 4173    # dist/ の表示確認
bun run test                     # シナリオ・進捗保存の単体テスト
bun run test:e2e                  # PC・スマートフォン幅のブラウザテスト
bun run check:design              # 各ページの撮影とはみ出しの確認
```

E2Eテストはインストール済みの Google Chrome を使います。Chromeがない環境では、PlaywrightのChromiumをインストールし、`playwright.config.ts` の各プロジェクトから `channel: 'chrome'` を外してください。

```sh
bunx playwright install chromium
```

E2Eテストの前には `bun run build` が必要です。4173番ポートでプレビューが起動済みなら再利用し、起動していなければテストが自動的に起動します。結果のJSONと画面画像は `test-results/`、失敗時のトレースはその配下に保存します。

## 静的ホスティング

`bun run build` で作成した **`dist/` の中身**を静的ホスティングへ配置します。バックエンド、認証、データベース、外部APIは使いません。

### GitHub Pagesに公開する

公開先URLは <https://101ta28.github.io/internet-literacy-lab/> です。[公開用ワークフロー](.github/workflows/deploy-pages.yml) は、`main` へのpush時に単体テストと本番用ビルドを実行し、両方が成功した場合に `dist/` を公開します。Node.js 22と、`package.json` の `packageManager` に指定したBunを使用します。

初回は、GitHubリポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。その後、ワークフローを含む変更を `main` にpushしてください。設定前にpushした場合は、**Actions → Deploy to GitHub Pages → Run workflow** で `main` を選んで実行します。

公開結果はActionsの `deploy` ジョブで確認できます。成功後、公開先URLを開いてください。以後は `main` へのpushごとに更新されます。単体テストやビルドに失敗した場合、公開済みのサイトは更新されません。ブラウザでのE2Eテストは公開ワークフローには含めず、必要に応じてローカルで実行します。

### 配信パスと画面URL

Viteの `base: './'` と React Router の `HashRouter` を使っているため、サブディレクトリへの配信にも対応します。サーバー側のページ振り分け設定は不要です。

- トップ：`/#/`
- 体験一覧：`/#/challenges`
- L01：`/#/challenges/suspicious-email`
- L02：`/#/challenges/social-footprint`
- L03：`/#/challenges/photo-privacy`
- L04：`/#/challenges/thoughtful-comment`
- L05：`/#/challenges/before-sharing`
- L06：`/#/challenges/too-good-to-buy`
- L07：`/#/challenges/sudden-warning`
- 解説一覧：`/#/knowledge`
- 学習の記録：`/#/progress`
- このサイトについて：`/#/about`

`file://` で直接開くのではなく、HTTPの静的サーバーを使ってください。初回読み込みには配信元への接続が必要です。起動後の模擬操作はブラウザ内で完結します。オフラインキャッシュを行うService Workerは実装していません。

## 体験の内容

| ID  | 模擬画面                           | 試せること                                                                                         |
| --- | ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| L01 | メール・配送確認サイト・公式アプリ | 差出人とURLの調査、架空情報の送信、中断、公式情報との比較、削除・報告、送信後の対処                |
| L02 | SNS投稿編集・過去の投稿            | 文章と画像の情報量の変更、公開範囲、第三者視点、情報の組み合わせ、投稿・削除                       |
| L03 | 写真編集                           | 拡大、人物・看板・私物の確認、顔・背景のぼかし、友人の条件付き同意、公開範囲、公開取り下げ         |
| L04 | 投稿・コメント欄                   | 人格攻撃と行動への批判の比較、言い換え、事実確認、相手・周囲の視点、取りやめ・削除・通報・ブロック |
| L05 | SNSの情報共有・主催者の発表        | 転載元・画像の日付・最新情報の確認、シェア・保留、出どころを添えた投稿、訂正・削除                 |
| L06 | 通販の商品ページ・注文画面         | 販売者・価格の比較、支払条件の変化、購入の見送り、模擬振込、未着時の記録・相談                     |
| L07 | 感染警告・サポートとの模擬通話     | 表示元の確認、ページとタブの操作の比較、通話の中断、遠隔接続の切断、支払後の対処                   |

すべての課題で、任意の3段階ヒント、発見記録、結果、操作履歴を使った振り返り、リセット、関連解説への移動を利用できます。体験の順序・解放条件やランキングは設けていません。

文章は教材に用意した候補・編集オプションを選んで変更します。自由入力欄、実際のパスワード入力、写真アップロード、AIによる採点はありません。画面上の人物・サービス・画像はすべて架空で、写真には自作のSVGイラストを使用しています。

## 教材を追加する

1. `src/features/challenges/scenarios/index.ts` に `Scenario` 型の定義を追加し、`scenarios` 配列へ登録します。IDとslugは既存と重複させません。
2. タイトル、カテゴリ、難易度、時間、目的、初期状態、表示状態、操作、遷移、発見、結果、3段階ヒント、関連記事ID、現実での注意点を定義します。
3. `app` で既存の模擬画面を選び、その画面が発行する操作IDと設定キーを揃えます。異なる操作が必要なら、`components/` に画面部品を追加し、`ChallengeWorkspace.tsx` の画面選択に登録します。模擬ブラウザなどの共通部品は `MockApps.tsx` にあります。
4. `src/features/knowledge/articles.ts` に記事を追加します。概要・問題・仕組み・注意・予防・対処・参考資料・更新日を設定し、`challengeIds` と教材の `knowledgeIds` を相互に紐付けます。
5. 安全な操作、リスクのある操作、途中の変更、異なる操作順、リセット、振り返りをテストし、PCとスマートフォン幅で確認します。

状態遷移は `transition(scenario, state, event)` に集約しています。操作には `allowed` 条件を付けられ、結果の計算は画面から分離します。`reset` は今回の画面・設定・履歴・発見・結果・ヒント・振り返りを初期化します。過去の進捗は別に保持します。

## プライバシーと進捗

保存先は `localStorage` の `internet-literacy-lab:progress:v1` です。課題IDごとに次だけを保存します。

- 体験済み・振り返り済みの状態
- 発見ポイントのID
- 最終体験日時

操作履歴、投稿本文、写真、編集設定は保存しません。保存データの読み込み時には型・日時・教材ID・発見IDを確認し、不明なフィールドを取り込みません。保存できない場合もメモリ上で動作し、利用者にそのことを表示します。進捗削除には画面上の確認が必要です。保存領域へアクセスできず削除を確認できない場合は、その旨とブラウザからの削除方法を表示します。

広告、解析、トラッキング、外部フォントはありません。参考資料へのリンクは、利用者が選んだときだけ外部サイトを新しいタブで開きます。CSPで外部のスクリプト・画像・フォーム送信を制限しています。

## 検証と制約

仕様書のMVPに、日常の判断を扱う3教材を追加しています。調査と実装の対応は [docs/content-research.md](docs/content-research.md) に記載しています。結果は起こり得る例で、危険の発生や法的判断を断定しません。解説の出典は各記事の「参考資料」から確認できます。

PC・スマートフォン幅、キーボード、フォーカス、保存不可時の動作を検証対象としています。WCAG 2.2 AAを設計目標にしていますが、第三者による適合監査や、すべての実機・支援技術での試験は行っていません。

次の開発では、実際の対象年齢の利用者による操作観察、iOS Safariを含む実機確認、専門家による教材レビューを検討できます。

デザインの適用範囲は [design.md](design.md)、再設計・検証の記録は [docs/redesign.md](docs/redesign.md) を参照してください。体験内のスタイルは `src/styles/experience.css` で維持し、サイト側のデザイン変更から分離しています。追加教材固有のスタイルは `src/styles/everyday.css` にあります。
