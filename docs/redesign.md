# サイトの再設計と体験画面の保護

Hallmark 2.0.0を使い、トップ・一覧・解説・進捗などのサイト画面を再設計した。体験用の仮想ブラウザや模擬アプリには、変更前の見た目と操作を維持する。

## 最終的な変更範囲

トップは架空の配送メールの引用を使う構成とし、体験一覧を2列に広げた。見出し・本文・余白を調整し、解説の目次や進捗の表示を整えた。サイトの色・書体・余白は `src/styles/tokens.css` に集約している。

体験画面を構成する `ChallengeWorkspace.tsx`、`MockApps.tsx`、`PhotoScene.tsx` は、再設計前のコミットと同一に戻した。体験用の既存CSSは値を保って `experience.css` に分離し、`.workspace-page` 内に限定した。サイトの共通スタイルからも体験を除外している。これにより、サイトのボタンや文字サイズを変更しても、仮想ブラウザ・SNS・写真・コメントの再現画面には適用されない。

シナリオデータ、状態遷移、保存処理、既存テストは変更していない。外部画像・フォントは追加していない。作業中に追加された開発用の `puppeteer-core` とロックファイル変更は保持している。

## 検証

ビルド・単体テストはエージェント環境で実施する。ローカル通信が `EPERM` で拒否されるため、E2Eは利用者の通常のターミナルで実行し、結果と画像をエージェントが読み取る。

Hallmark自体の描画検査は、`puppeteer-core` の追加後にも実行を試みたが、Chrome起動時の `setsockopt: Operation not permitted` で実行できなかった。画面確認には導入済みのPlaywrightを使用した。サイトの再設計段階では既存E2E20件が成功し、7ページ・17条件で要素のはみ出しとJavaScriptエラーは0件だった。体験の復元後もE2E20件が成功した（開始 `2026-11-05T12:13:28.083Z`、所要約23秒、失敗・スキップ・不安定なテストなし）。メール・投稿・写真・コメントの保存画像を確認し、メールと写真は再設計前の画像とも比較した。仮想ブラウザの枠、URL欄、図版、操作部の復元を確認している。

体験内の既存デザインにはHallmarkの装飾規則を適用しない。仮想ブラウザなどを維持する利用者の指示を優先する。サイトの変更前後は `.hallmark/compare.html`、操作中の体験画像は `test-results/` に保存する。

体験を除いたサイトの静的検査は重大指摘0件。書体の例外判定などの警告は残っているため、完全な自動判定通過とは扱わない。体験内の原本CSSは、見た目を維持する目的で値を変更せずに分離した。
